# 共享账号档案柜：服务器存储设计

## 目标

把当前只保存在浏览器 `localStorage` 的账号档案改为 Visa 服务器上的单一共享库：所有通过现有网页门禁的设备看到同一份数据，A 设备已有资料首次自动迁移，之后由服务器作为唯一来源。

## 已确认决策

- 所有使用当前 `vault` Basic Auth 的设备共享同一份账号库，不增加第二套用户账号体系。
- 页面打开或手动刷新时同步；导入、备注、删除、清空立即同步；不做实时轮询。
- 服务器不可用时显示同步错误并禁止写入，避免离线分叉。
- 服务器保存 SQLite 数据库，敏感记录使用 AES-256-GCM 加密。
- 加密密钥只保存在 Visa 服务器 root 权限文件中；密钥丢失时加密数据无法恢复。
- 每日备份数据库和恢复所需密钥，保留最近 7 份，备份目录仅 root 可读。

## 不包含

- 多用户独立库、邀请成员、细粒度权限。
- 端到端加密：服务器需要解密记录并返回给已通过网页门禁的浏览器。
- 外部托管数据库或第三方同步服务。
- 离线编辑队列和实时协同编辑。

## 架构

```text
浏览器 A/B
   │ HTTPS + Basic Auth
   ▼
edge-proxy → appleid-vault (静态页面 + 门禁)
                    │ Docker 内网
                    ▼
              vault-api (SQLite + AES-GCM)
                    │ 持久化挂载
                    ├─ /root/appleid-vault/data/vault.db
                    ├─ /root/appleid-vault/secrets/vault.key
                    └─ /root/appleid-vault/backups/
```

`vault-api` 不映射宿主机公网端口，只允许 `appleid-vault` 通过 Docker 内网访问。Nginx 在门禁认证之后转发 `/api/vault/*`，并关闭这些接口的访问日志，避免账号内容或取码 URL 进入日志。

现有取码代理继续复用同一内网服务，外部取码请求仍限制为公网 HTTP/HTTPS 目标、最多 3 次跳转、最多 1 MiB 响应。

## API 契约

所有接口均位于同源路径 `/appleid/api/vault/`，由 Nginx Basic Auth 保护。

- `GET /state`：返回 `{ revision, records }`，返回解密后的完整档案列表。
- `POST /sync`：接收当前浏览器档案列表、迁移标记和删除/清空水印；服务器在事务内按账号合并后返回最新完整状态。
- `POST /clear`：全局清空，写入清空时间水印并返回空状态。

服务器只把完整状态作为一个加密 SQLite 记录保存。档案规模较小，整包读写能保持实现简单，并由 SQLite 事务保证同一时刻只有一个写入者。

## 合并和迁移

- 账号字符串是唯一键。
- A 设备首次启动先读取服务器状态，再把旧 `localStorage` 中的记录发送到 `/sync`；服务器按账号合并，`updatedAt` 较新的记录胜出，服务器已有记录在时间相同或更晚时保留。
- 服务器返回成功后删除浏览器中的完整旧库；失败则保留旧数据并禁止继续修改。
- 删除操作产生账号级删除水印，防止另一台设备的旧快照把已删除账号重新写回。
- 清空操作产生全局清空水印；只有明确在清空之后修改的记录才允许重新出现。
- 每次成功写入都递增 `revision`，页面刷新和手动刷新以服务器返回状态替换当前状态。

## 加密和隐私

- 首次部署生成 32 字节随机密钥，权限设为 `0600`，不写入 Git、网页、容器日志或 API 响应。
- 每次保存使用新的随机 nonce，AES-GCM 的认证标签用于检测数据库篡改。
- 账号、密码、密保、手机号、备注和取码信息均位于加密载荷中；数据库只保留加密状态、版本和必要的时间元数据。
- API 不记录请求体；Nginx 关闭共享库和取码代理 location 的访问日志。
- HTTPS 传输和 Basic Auth 保护访问过程；服务器 root 权限或密钥文件泄露仍属于完全失陷场景。

## 前端行为

- 页面初始化显示同步状态，完成服务器拉取后再显示档案。
- 检测到旧 `localStorage` 数据时自动执行一次迁移，并提示迁移结果。
- 导入、编辑备注、删除和清空先调用服务器；成功后用服务器返回状态更新 UI，失败时保留当前文本/状态但禁止继续写入。
- 保留 `localStorage` 仅用于首次迁移期间的恢复，不再把它当作长期数据源。
- 现有折叠卡片、复制、显密、短信验证码和搜索行为保持不变。

## 部署和备份

- 为 API 服务构建固定版本的 Python 镜像，安装 `cryptography`，以非 root 用户运行。
- 数据库、密钥和备份目录从宿主机只读/读写按需挂载；API 容器 root filesystem 保持只读。
- 每日备份使用 SQLite 一致性备份，复制数据库和密钥到 root-only 目录，清理超过 7 天的备份。
- 部署前保留现有站点配置与数据副本；API 健康检查、Nginx 配置检查和门禁回归通过后再切换前端。

## 验证标准

- A 设备已有记录首次打开后能自动迁移，迁移成功后 A/B 设备显示相同档案。
- B 设备导入、备注、删除、清空后，A 设备刷新能看到结果。
- 同账号冲突按 `updatedAt` 合并；删除水印不会被旧快照复活。
- 数据库内容不是明文；错误密钥或篡改载荷会被拒绝。
- 未认证 API 返回 401，错误密码仍被拦截，API 容器无公网端口。
- 服务器不可用时页面显示同步失败，不会静默写入本地分叉数据。
- 现有取码代理、验证码 6 位提取、时间排除、折叠卡片和一键复制回归通过。

## Route Deviation

从纯静态 `localStorage` 方案扩展为同域服务器 API，是为满足用户明确提出的 A/B 设备共享和服务器加密存储需求；不引入第三方云服务。

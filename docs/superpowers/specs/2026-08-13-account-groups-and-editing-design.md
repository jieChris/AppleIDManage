# 账号分组与资料编辑设计

## 目标

在现有共享档案柜中加入文件夹式分组、组内排序、主号、手动完善状态和资料编辑。保留现有紧凑卡片高度与共享加密存储；账号和登录密码只读，其余资料可编辑。

## 已确认交互

- 现有账号迁移到虚拟的“未分组”，原数据不改名、不丢失。
- 用户可以新建、改名、删除分组。删除分组只把账号移回“未分组”，不删除账号。
- 每个正式分组最多 6 个账号；前端在移动时阻止超限，服务器在并发冲突时把溢出账号退回“未分组”。
- 每组最多一个主号，但允许暂时没有主号。主号不强制排第一，排序由用户单独控制。
- 组内使用上移/下移按钮排序；“未分组”不提供排序和主号。
- “完善 / 未完善”为手动标记。旧账号按现有完整性规则初始化；完善卡片使用绿色整列强调，未完善使用黄色。
- 账号、登录密码不可编辑，仍可复制和显隐。密保问题、出生日期、国家、手机号、取码链接、备注、副邮箱、专用密码均可编辑。
- 副邮箱和专用密码使用原卡片 4×3 信息网格：账号、登录密码和手机号取消双格占位，备注占两格，因此桌面端不增加信息区高度。

## 数据结构

共享加密状态新增：

```js
{
  groups: [{ id, name, updatedAt }],
  deletedGroups: { [groupId]: timestamp },
  records: [{
    ...existingFields,
    secondaryEmail: string,
    appPassword: string,
    profileStatus: 'complete' | 'incomplete',
    groupId: string,
    groupOrder: number,
    isPrimary: boolean
  }]
}
```

分组删除使用水印，避免旧设备快照复活文件夹。新版前端发送 `schemaVersion: 2`；旧版页面未发送该版本时，服务器在合并较新记录时保留新版分组、状态、副邮箱和专用密码字段，避免旧标签页覆盖新资料。

## 同步与约束

- 分组按 `id` 和 `updatedAt` 合并，删除水印和全局清空水印优先。
- 账号仍以账号字符串为唯一键、以 `updatedAt` 决定冲突胜负。
- 每次写入后服务器统一修正无效分组引用、连续排序、每组最多 6 个和单一主号。
- 客户端只接受 revision 不小于当前 revision 的响应，避免较旧刷新覆盖较新写入。
- 导入同名账号时保留账号、登录密码和全部新增管理字段；普通导入不会把已分组账号移回未分组。

## 页面结构

- 档案工具栏新增“新建分组”。
- 列表按文件夹区块渲染；分组头显示名称、数量 `n/6`、主号账号，并提供改名和删除。
- 账号摘要继续可折叠，增加主号、状态、上移、下移和编辑操作。
- 编辑态在原网格中把可编辑字段替换为输入框，取码链接在原验证码工具条内编辑；保存后整包同步，失败则保留编辑态。
- 搜索覆盖账号、手机号、副邮箱、备注和分组名；左侧完善统计与筛选改用手动状态。

## 导出兼容

原 7 字段账号行和手机号行不变；导出追加可选元数据行：`副邮箱|...`、`专用密码|...`、`备注|...`、`分组|...`、`标记|完善/未完善`、`主号|是`。解析器识别这些行；未包含元数据的旧文本继续正常导入。

## 验证标准

- 旧的加密状态无损迁移，新旧页面同步不会清除新增字段。
- 分组新建、改名、删除、移动、排序和主号设置跨刷新及跨设备保留。
- 第 7 个账号不能进入分组；并发异常状态也由服务器收敛到最多 6 个和一个主号。
- 除账号和登录密码外的资料可保存；账号和登录密码没有编辑控件。
- 桌面端信息网格仍为三行，完善为绿、未完善为黄。
- 全量导出再导入可恢复新增字段和分组归属。
- 原解析、复制、显密、验证码、门禁、共享同步、删除和清空功能回归通过。

## Route Deviation

项目没有 `.trellis` 目录，无法加载 Trellis 包级规范；沿用仓库现有 `docs/superpowers` 规格、计划和执行记录格式，功能范围不变。

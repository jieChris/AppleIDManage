# Apple ID 账号管理器设计

## 目标

制作一个可直接在浏览器打开的本地单页工具，用于管理以下固定格式的账号资料：

`账号----密码----密保问题1----密保问题2----密保问题3----出生日期----国家`

每条账号资料可以紧跟一行手机号和取码链接：

`手机号|取码链接`

核心体验是：批量粘贴、快速解析、搜索定位、单击复制。敏感数据只保存在当前浏览器的 `localStorage`，不上传服务器。

## 范围

### 包含

- 多行文本粘贴与逐行解析。
- 连续短横线（如 `----`）、带空格的单短横线（如 ` - `）或连续空格/Tab 作为字段分隔符。
- 7 个字段的预览、缺字段提示和重复账号提示。
- 账号行下面的手机号与取码链接识别。
- 取码链接响应内容中的 6 位验证码解析、显示和复制。
- 重复账号按账号更新已有记录。
- 本地保存、搜索、删除单条记录、清空全部记录。
- 点击字段值复制到剪贴板；密码默认隐藏，可单独显示。
- 空状态、导入反馈、复制反馈、移动端适配。

### 不包含

- 云同步、账号登录、多人协作或服务端数据库。
- 真正的密码学加密。`localStorage` 适合本地便利工具，不等同于安全密码库。
- 取码接口必须允许浏览器跨域读取（CORS）；否则浏览器只能显示链接并提示“无法读取”，不能绕过网站安全策略。
- 自动生成密码、导出文件、浏览器插件等扩展功能。

## 参考方向

交互模式参考开源密码管理器的“侧栏筛选 + 搜索 + 详情字段 + 掩码敏感值”结构：

- [Bitwarden clients](https://github.com/bitwarden/clients)：成熟的保管库导航和复制反馈。
- [Padloc](https://github.com/padloc/padloc)：轻量、清晰的密码条目展示。

只借鉴信息架构与使用习惯，不复制品牌素材。视觉采用深色档案柜风格：石墨黑背景、暖白卡片、荧光黄绿作为动作色，并用等宽字体突出账号数据的工具属性。

## 信息架构与交互

### 页面布局

- 顶部品牌区：工具名、数据仅本地提示、清空全部操作。
- 左侧导航区：总数、完整记录数、待检查数，以及“全部/待检查”筛选。
- 主内容区：
  - “批量导入”面板：文本框、示例格式、解析按钮、解析结果统计。
  - “账号档案”列表：搜索框、记录卡片、字段复制按钮、显示密码按钮、验证码状态、刷新取码和删除按钮。
- 小屏幕下侧栏转为顶部横向统计，卡片改为单列。

### 解析规则

1. 以换行分割记录，忽略空行。
2. 优先使用包含两个及以上短横线的分隔符（允许两侧有空白）。
3. 若字段之间使用带空格的单短横线（` - `），按该形式分割；未使用短横线时，使用连续空格或 Tab 分割，保留字段内部的单个空格。
4. 仍不足 7 个字段时，标记为失败行，不写入数据。
5. 多于 7 个字段时，将多出来的片段并入国家字段，避免静默丢数据。
6. 账号为空时标记为失败行；出生日期和国家允许为空，但该记录会进入“待检查”。
7. 导入成功后，以账号作为唯一键更新已有记录。
8. 账号行后紧邻的 `手机号|URL` 行归属于该账号；手机号直接显示，URL 以链接形式保留。
9. 导入后自动尝试读取取码 URL；用户也可以在记录卡片上手动刷新。

### 取码解析规则

- 仅对 `http` 或 `https` URL 发起 `fetch`，读取响应文本，不执行响应中的脚本。
- 优先匹配“验证码 / 验证码是 / OTP / code / verification code”等上下文后面的独立 6 位数字。
- 没有上下文时，只接受不属于更长数字串、日期、时间或带 `:`、`/`、`-` 分隔的时间片段的独立 6 位数字。
- 找不到符合条件的候选时显示“无验证码”，请求失败或被 CORS 拦截时显示“无法读取”，两者不混淆。
- 记录上次读取状态和时间，防止每次渲染都重复请求；刷新按钮允许主动重试。

### 数据结构

```js
{
  id: string,
  account: string,
  password: string,
  questions: [string, string, string],
  birthDate: string,
  country: string,
  phone: string,
  codeUrl: string,
  smsCode: string,
  codeStatus: 'idle' | 'loading' | 'found' | 'empty' | 'blocked',
  codeCheckedAt: string,
  updatedAt: string
}
```

## 技术方案

- `index.html`：页面骨架与可访问的按钮/表单元素。
- `styles.css`：所有布局、主题、响应式和动效；无 CSS 框架。
- `app.js`：解析器、`localStorage` 存取、渲染、复制与事件委托。
- 取码读取使用浏览器原生 `fetch`；不增加代理服务。
- 不引入构建工具和第三方依赖，使用浏览器原生 Clipboard API，剪贴板不可用时提供降级提示。

## 错误处理与隐私提示

- 解析失败只影响当前行，其他合法行仍可预览和导入。
- `localStorage` 读取损坏时回退为空列表并提示用户，不覆盖原始文本输入。
- 清空全部数据需要二次确认。
- 页面明确提示：数据只保存在本机浏览器，清理站点数据会导致资料丢失。
- 页面明确提示：取码链接是否能自动读取取决于目标接口的 CORS 配置；可以打开链接查看，但不代表当前页面能读取其响应。

## 验证标准

- 能识别短横线分隔和连续空格分隔的 7 字段记录。
- 缺字段行不会写入，且有可读反馈。
- 重复账号导入后只有一条最新记录。
- 刷新页面后记录仍存在。
- 点击账号、密码、密保问题、出生日期、国家均能复制对应值。
- 手机号可直接显示并复制；取码链接可打开；合法 6 位验证码可单击复制。
- 时间、日期、长数字串不会被误显示为验证码；无候选显示“无验证码”，跨域/网络失败显示“无法读取”。
- 搜索、筛选、显示/隐藏密码、删除、清空均可用。
- `app.js` 包含一个轻量 `assert` 自检，覆盖解析器的关键边界。
- 不依赖外部浏览器；完成后使用 Codex 内置浏览器进行交互和视觉检查。

无。按已确认的纯静态本地方案执行。
